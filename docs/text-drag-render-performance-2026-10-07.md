The user clarified that text position follows dragging, but rendered text does not update fluidly. This pass targets rendered canvas feedback, preserving box-only resizing and existing typography behavior.

## First hypothesis

The transaction preview scheduler deliberately waits for an in-flight render rather than cancelling it on every pointer tick. However, the result handler compares the completed layer-composite job against per-input edit and layer revisions. Another move invalidates that signature, so the completed frame is discarded even though it belongs to the same active drag.

The candidate carries the existing edit transaction generation into render requests/results. It permits intermediate interactive layer-composite feedback only while that transaction, asset, file, preview generation, and mask revision remain current. Release, cancellation, a new transaction, changed source/masks, and full-resolution work retain strict rejection. Final state, persistence, and grouped undo semantics remain authoritative.

[Qt scene graph documentation](https://doc.qt.io/qt-6/qtquick-visualcanvas-scenegraph.html) explains the distinction between GUI synchronization and frame presentation. [Qt performance guidance](https://doc.qt.io/qt-6/qtquick-performance.html) supports measuring repeated bindings and rendering work separately. Frame callbacks alone do not prove text pixels changed; this probe also records preview revisions and captures the presented canvas with transform guides hidden.

## First candidate result and second hypothesis

The first candidate reduced the first preview callback from 3168 ms to 961 ms (70%) and delivered six callbacks before the last move at 3125 ms. However, only the first callback advanced the native texture revision; the remaining CPU image updates did not advance it until after movement ended. This does not qualify as continuous native rendered feedback. [Candidate 1 metrics](evidence/text-drag-render-2026-10-07/candidate/text-drag-perf-candidate.json) retain that distinction.

The second attempt investigates native publication after CPU result acceptance. Asynchronous Metal completion currently checks the preview request generation, which can advance when the next render starts during the same gesture. A safely accepted intermediate frame can therefore lose its display upload. The probe now separately counts native revision advances during movement rather than accepting CPU callbacks as sufficient evidence.

Candidate 2 passed the native gate: nine texture revision advances during movement, first native update at 357 ms, and median spacing of 289 ms. The fixture hash matches the baseline, and the hard checks for style, scale, rotation and exact undo/redo passed. The JSON-only scale/rotation booleans incorrectly compared QVariant against QJsonValue; the later probe fixes this reporting mismatch. [Candidate 2 metrics](evidence/text-drag-render-2026-10-07/candidate2/text-drag-perf-candidate.json) are retained, along with its frozen executable hash.

## Third hypothesis

Layer position affects the Layers stage and its suffix, while Decode through Look have dependency-scoped identities independent of position. Ordinary drafts suppress all stage-cache writes, and working fusion skips intermediate cache entries. The third attempt uses the existing draft resolution from the first active transform frame, retains only the pre-Layers stages in the existing bounded cache, and avoids fusion across that reusable prefix during the gesture. Layers and downstream stages continue to render without adding transient cache entries. Release schedules the original full-resolution path. Accept this optimization only if native update spacing improves by at least 20% versus candidate 2, with correctness guards passing.

The initial third run missed the gate: native spacing regressed to 775 ms despite worker totals of 130–139 ms and cache hits through Look. Accepted render generations skipped 13 → 17 → 22. Source inspection found that a finished QFuture reports `isRunning() == false` before its queued GUI completion consumes the result. The transaction timer can replace that future and advance the generation first. This is a correctness race exposed by faster rendering, rather than another independent optimization. Add one bounded corrective validation of an explicit pending-result handoff; if it still misses the native-spacing gate, remove the prefix optimization and retain the proven native-publication repair. The initial third-run artifact remains in `candidate3/`.

The corrective handoff passed two native runs: 14 texture updates during motion in each, first updates at 230/254 ms, and median native spacing 209/211 ms. The median of run medians improved from 271 ms for candidate 2 to 210 ms (23%). Render generations are consecutive, worker totals are about 136–166 ms, and the final native image is 1929 × 1197. Style, scale, rotation and exact undo/redo guards all passed. Peak memory footprints of 2.05/2.10 GB did not exceed the comparable candidate 2 repeat's 2.20 GB; this is a guard, not a claim of memory reduction.

## Remaining publication check

The scheduler loop is accepted. A separate, one-attempt publication check uses its frozen executable as the new baseline and asks whether the paint-tile display-image requirement causes unnecessary CPU publication during an active layer transform. Compare mode, active paint jobs, and full-resolution release keep their existing CPU requirements. A different paint gesture cannot begin during a transform transaction and take the obsolete CPU provider frame. Native output eligibility and existing CPU fallback remain authoritative. Accept only if native spacing improves by at least 20% against the accepted handoff runs; otherwise revert this publication experiment without further iterations.

This publication experiment was rejected and reverted, including its paint-start guard. It delivered the same 14 native updates and 212 ms median spacing. Instrumentation showed CPU images, no native output surfaces or GPU-to-CPU transfer, and 101–108 ms in output conversion. The proposed readback requirement was therefore not the remaining bottleneck in this fixture. The final code retains the original CPU paint-base requirement. Further output-conversion optimization needs its own fidelity-qualified work; this pass makes no high-frame-rate smoothness claim.

## Accepted behavior

- Intermediate CPU and native frames may publish during the same active edit transaction, with asset, path, mask and transaction-token isolation.
- Interactive futures stay reserved until their GUI completion consumes the result; finished workers cannot lose frames to the next transaction timer tick.
- Active transforms use bounded drafts and reuse dependency-stable pre-Layers stages without caching transient layer positions.
- Release returns to the original full-resolution path. Box resizing, text style, rotation, grouped undo/redo and persistence calls retain their existing semantics.

The accepted native evidence is in [handoff run](evidence/text-drag-render-2026-10-07/candidate3-handoff/text-drag-perf-candidate.json) and [confirmation run](evidence/text-drag-render-2026-10-07/candidate3-confirm/text-drag-perf-candidate.json). The user’s open process was not restarted; the on-disk repository-launched app bundle is rebuilt separately for the next launch.

## Final correctness review

Independent review identified a linked-source edge case: a linked layer's file may change while the same transform transaction remains active. The layer revision changes for ordinary movement as well, so it cannot identify source changes independently. A separate source-content epoch now travels with the request, result and native commit context, and invalidates intermediate feedback when the linked-source monitor reports changed files. The transaction token remains unchanged so queued transaction-end callbacks still close the gesture. This is an isolation correction, not another performance experiment.

Regression probes also needed current assumptions: live draft dimensions derive from the request rather than a hard-coded 960-pixel size, geometry scrolling waits for expanded layout settlement, and path editing selects one stable text-layer ID while multi-selection is enabled only for shared formatting. Initial failed logs remain available alongside the reruns.

The expanded workflow exposed a genuine pre-existing typography failure as well: a font/face update removed the axes field and forced version 3 even on version 5–8 path or material styles. Their retained advanced fields then failed strict decoding, and shared Bold rolled back. Font changes now reset font-specific axes while retaining the existing schema version, contour and material data. Regression checks cover individual advanced styles and shared typography, with exact undo restoration.

Later broad reruns overlapped unrelated release and desktop builds, including another Ninja process writing the same Debug test folder. Initial-preview waits timed out under that contention. Those logs remain in `tests-accepted.log`; they are not performance acceptance artifacts. Final controller/workflow/Studio executables were copied to distinct `*_final_proof` names in the same test directory, with hashes retained in `frozen-proof-binaries.sha256`, before isolated reruns. An empty default face is valid for the measured variable-font fixture; the regression uses that fixture directly.
