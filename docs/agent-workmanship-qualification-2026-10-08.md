# Agent qualification — October 8, 2026

This pass qualifies a specific editable cover workflow before making broader
claims about agent autonomy. Three Luna agents at xhigh worked on typed
generation, bounded repair, and native visual acceptance. The root integrates
their work and runs the real installed local model and application.

## Required outcome

The model must choose the construction tools and create three editable lines
on the existing alpine photograph: `SAMPLE / FIELD NOTES 01`,
`AFTER THE LIGHT`, and `A STUDY IN BLUE HOUR`. Preserve the original photo,
framing and color. Require deliberate hierarchy, left alignment, safe margins,
available native font faces, and visibly warm-white ink. The app qualification
also requires a headline-only revision, durable Catalog save, Preview reload,
identical re-export, visible planning Stop/retry, and exact whole-task Revert.

The [acceptance contract](evidence/agent-workmanship-2026-10-08/README.md)
records the exact briefs, gates, commands, and limits. The model chooses the
actual construction calls; the test driver orchestrates the app's ordinary
review, save, export, reopen and Revert controls. That orchestration must not be
reported as model-owned Export-domain authority.

## Defects found through execution

- Native generation needs operation-specific arguments and whole-plan
  validation against the original tool schema. Invalid plans must execute
  nothing and return exact rejected calls and schema errors for correction.
- Repair must retain returned native IDs and successful work, stop identical
  rejected plans, and reset its correction allowance after actual progress.
- Completion requires successful native mutations followed by fresh readback;
  an empty unfinished intent is not completion.
- The sample harness omitted production's frozen approval context. It now
  supplies the same scoped snapshot on each planning turn.
- Native font inspection returned families without the faces the model needed.
  The planner then dropped the newly added face inventory during compaction.
  Both producer and bounded context projection now carry the inventory.
- White text entered the scene layer stack before photographic output and
  became gray. A bounded display-text suffix preserves authored SDR ink. The
  system-monitor ICC integration test also found and fixed double composition
  in the geometry prefix; it now passes authored-color, edge, mask and
  unchanged-background checks through the real monitor profile on the original
  fixture. The varied-background regression now passes matched CPU/CPU
  preservation and the real monitor ICC transform. Native retained-surface
  publication versus CPU image publication can differ by one channel value;
  that separate backend transition is recorded, not claimed as exact parity.
- The real model repeated font reads despite the correct inventory and prompt.
  A real-provider decoder probe isolated incompatible mixed schema branches
  and sensitivity to schema property order. The grammar-compatible projection
  now constructs native text; the host still validates the whole plan against
  the original canonical schema before any call executes.
- Async continuation now preserves each historical bound quality assessment instead of replacing it with a later recipe's passing review. Invalid terminal model output cannot fall back to successful generic composition work; positive completion and failed-completion exact Revert are both covered.
- The controller omitted validated detail crops from the critic request. The
  repair proof now passes the pinned overview and exact detail metadata through
  the normal critique handoff. Prior review context also drops duplicated
  presentation diagnostics while preserving semantic evidence. All four
  focused bridge contracts now pass, including critique and repair.

## Boundary of the result

Production `main.cpp` still enrolls Library, Carousel, Scene, Export,
preferences and jobs with an unavailable resource-owner classifier. Photo and
Timeline tools do not grant those domains editing authority. Reliable
completion across the whole app still requires their scoped resource adapters,
durable save/reopen/export receipts, and matched end-to-end tests.

A read-only production audit also found an admission gap for Timeline: the
main task begins from photo asset IDs, while Timeline commands require the
approved task target set to contain its `timeline:<id>`. The controller selects
sample/batch phases from photo count and has no Timeline-specific task entry.
The existing multi-document contract uses a permissive test authorization
callback, so it does not qualify that production gate. The next concrete step
is a scoped Timeline target/admission path, native baseline enrollment and
matched allowed/out-of-scope/Revert/reopen proof before claiming end-to-end
video agent capability.

Planning Stop checks do not qualify cancellation of in-flight pixel workers.
Catalog refresh and Preview reload are same-process reopen, not quit/relaunch.
Neither a passing model review nor a focused native test qualifies all design
taste, print output, HDR, sustained video performance, or every possible task.
