# Timeline Shared Color Engine Integration

This plan carries the video timeline from its current FFmpeg color-filter path to the same color decision and render engine used by photo editing. It preserves the existing timeline model, effect stack, render cache, export queue, undo, and recovery behavior while moving video color work onto the shared engine.

## Current implementation

- The video color engine now owns source-signal metadata resolution for both the QVideoFrame preview adapter and FFmpeg delivery: recognized matrix/range/transfer/primaries tokens, unknown-tag defaults, HDR and Rec.709 classification, output tags, and limited-range camera-code restoration are resolved through one policy. The preview CPU sampler uses shared Kr/Kb coefficients for supported matrices and falls back to Qt for non-constant-luminance/opponent matrices it cannot represent; delivery continues to decode through FFmpeg `scale`/`zscale`. This aligns source decisions while decoded preview/export frame parity remains unmeasured.
- The monitor combines eligible pointwise stages into one RGBA64 pixel scan: Sony camera conversion, a static photo-engine base grade, and exposure/contrast/saturation/fade/monochrome/punch adjustments when their ordering permits. It preserves the existing RGBA64 quantization between logical stages and keeps animated or spatial grades on their renderer routes. These combinations remove full-frame read/write walks without allocating another image; telemetry reports the combined duration as `fusedColorPipelineMs` (or `cameraAndBaseGradeMs` when only those two stages are fused).
- `TimelineDocumentController::Clip` stores an optional explicit Sony source pair (S-Log2/S-Gamut, S-Log3/S-Gamut3, or S-Log3/S-Gamut3.Cine) alongside the external CUBE path, bypass flag, shot-match gains, and a versioned photo-engine grade recipe. The recipe is saved with the clip, included in render identity, and participates in undo and clip copy/replace. The preview sends recipes through the full photo-engine frame renderer; static pointwise grades and unmasked adjustment layers use validated CUBEs in sequence export; animated grade clips and spatial grades use the bounded full-frame stream. The Color inspector displays Qt decoder-reported frame size, pixel format, color space, transfer, range, and peak luminance for the matching current Program clip; `timeline.inspect_clip_color` returns those transient tags plus the completed preview conversion path and any warning when the requested clip matches. The source metadata inspector also displays generic FFmpeg color fields and a bounded selection of raw gamma, gamut, log, LUT, primaries, transfer, and color tags. The read-only `timeline.inspect_clip_source_color_metadata` tool returns the same source-file evidence by stable clip id without exposing the path or selecting a profile. Automatic mode applies a Sony S-Log transform only for an exact, unambiguous pair of supported `Gamma for Look` and `Color for Look` tags; conflicting, incomplete, or unrecognized tags leave the input transform unset. Users can choose automatic detection, a manual profile, or a manual bypass in the inspector or MCP, and the selected source is persisted with the clip. The source metadata inspector reports the same evidence and suggestion without changing the profile. Generic transfer and primaries tags alone do not identify a camera log profile. The preview uses reported matrix, range, transfer, and primaries to normalize common SDR YUV layouts into Rec.709 before ordinary grading, and reports when a layout must fall back to Qt conversion. Mapped YUV conversion samples directly into the monitor-sized image, avoiding a full-resolution intermediate when playback is downscaled. Mapped YUV layouts selected for a manual camera transform use RGBA64 staging, preserving 8-bit source precision through the transfer curve and keeping 10-bit and 16-bit source precision through S-Log transforms, photo-engine grading, timeline color effects, blur, shot matching, and creative LUTs; conversion to 8-bit occurs at the QML monitor boundary. Hardware-only layouts and PQ/HLG without a manual camera transform still use Qt conversion. The Color inspector warns that this HDR preview conversion is not shared with timeline delivery; a manual S-Log selection that conflicts with PQ/HLG decoder tags also raises a warning. The preview adapter is not yet shared with delivery. Source-clip spatial export outside the bounded opaque single-layer case, detail/geometry parity across every timeline placement, and measured preview/export parity remain open.
- The local MCP catalog exposes color inspection, input-transform set/clear, creative CUBE set/clear, bounded per-channel shot-match gains, and grade-recipe inspect/set/clear by stable clip id. `timeline.open_program_comparison` seeks to a requested visible clip frame (the midpoint by default), opens the existing split, wipe, overlay, or difference UI, and captures that Program frame as an iterative reference without changing edit history. Typed adjustment-layer edits can add, replace, move, enable, set opacity, choose a supported blend mode, set a supported grade parameter, and remove a layer by stable id; recipe validation and the existing undo path apply to every mutation. MCP can also create transparent timeline adjustment clips at explicit sequence times and set opacity by stable clip id. Video clips and timeline adjustment clips both accept shared photo-engine grade recipes; adjustment-clip grades apply to the picture composite beneath them. The effect-stack interface edits these clips through add, remove, reorder, clear, enable, and set amount. Amount changes preserve existing animation and update the value at the sequence playhead; unanimated values remain clip-wide. Stable-id keyframe edits accept `grade:<parameter>` for the clip's ten global controls and nine three-way wheel channels, plus `grade:layer:<stable-layer-id>:<parameter>` for the same controls inside a photo adjustment layer. The inspector exposes keyframe toggles for base and selected-layer grade controls, and the generic curve editor and MCP keyframe operation use the same clip-local timing, interpolation, undo, and save path. Animated grades use a retained per-clip photo-engine render session in preview, updating scalar state without serializing a recipe or rebuilding masks and the render plan per frame. Animated grades are delivered through the bounded shared full-frame stream. Playback/export performance measurements and decoded preview/export parity remain open.
- Agent tools can request the bounded Program scopes capture and read compact RGB/luma mean, percentile, and near-black/near-white summaries. Results identify the capture revision, sample count, and 480x270 maximum dimensions; they measure 8-bit SDR monitor output rather than source-linear or HDR pixels. Capture is rejected while Program Comparison or Full Screen Program is active.
- The engine computes Sony S-Log2/S-Gamut and S-Log3/S-Gamut3 transforms from normalized source code values through source-gamut conversion into linear Rec.709. A 65³ direct Rec.709 cube is now built once per profile, validated against the exact engine transform, and shared by the live monitor and FFmpeg delivery; delivery caches the same table as a CUBE sidecar. When that cube misses its p99 0.0015 or maximum 0.005 error gate, preview falls back to the exact scalar transform and delivery keeps the staged bridge. The staged FFmpeg bridge uses a profile-specific 16,385-entry decode shaper, a 2³ linear gamut-conversion cube, and a floating-point asinh shaper followed by a 16,385-entry BT.709 OETF table. The nonlinear output shaper allocates samples around shadows and midtones while covering the full extended range from the gamut-conversion cube. The S-Log2 LUT builder checks Sony's 0%, 18%, and 90% code anchors; existing engine checks cover both S-Log3 profiles against Sony code anchors and validate the combined input transform on a 23³ grid. Generated tables are cached on disk. These technical conversion stages run before the existing FFmpeg effects, shot-match gains, and creative CUBE.
- `clipEffectsFilter()` builds the ordinary exposure, contrast, saturation, monochrome, fade, punch, and blur stack in FFmpeg. For pointwise recipes, it samples the photo-engine pipeline plus unmasked adjustment layers on a 33³ Rec.709 grid, then compares tetrahedral CUBE interpolation against the exact photo-engine frame renderer on a 23³ validation grid. It keeps 33³ when p99 error is at most 0.0015 and maximum error at most 0.005; grades outside that gate are resampled at 65³ and, if needed, 97³ before the same gate rejects them. The agent inspection result reports the validation outcome, sample count, selected cube size, p99 error, and maximum error, and export preflight uses the same compiler and cached validated sidecar. The validated, content-addressed CUBE sidecar is inserted after the technical input transform. Preview applies that cube with the engine's tetrahedral evaluator; FFmpeg delivery uses tetrahedral `lut3d`. Recipes with masks, spatial detail, geometry, or image-dependent work use the photo-engine full-frame renderer in preview. Sequence export sends supported spatial grade placements one RGBA frame at a time through the shared photo-engine renderer. Top adjustment stacks run after FFmpeg composites lower layers; a single opaque source-video clip can use the route when it fills the sequence frame and has no overlapping picture layers or unsupported clip operations. The route can write the master and PNG sequence from that same frame pass. Pointwise grades above the spatial layer use the same photo-engine frame route so layer order stays intact. Adjustment-track delivery preserves animated clip and track opacity; it rejects extra visual effects on routed adjustment clips, overlapping clips on their tracks, and any active non-adjustment visual layer above the grade stack. Source-clip delivery requires full-frame geometry and 100% static opacity, rejects overlapping picture layers, and requires square-pixel opaque input. Both frame-stream routes reject alpha or two-pass delivery. Other spatial placements still need the shared frame graph in delivery. Shot-match gains and the external creative CUBE follow the shared grade. The in-memory grade-LUT LRU is bounded by eight entries and 64 MiB of table payload; its disk cache is pruned to 64 MiB.
- The primary Program monitor receives `QMediaPlayer` frames through `QVideoSink`. A single-flight worker keeps at most one newest pending decoder frame, downsizes before applying surface and frame rotation/mirror flags, applies a profile-specific 65³ Sony S-Log-to-Rec.709 cube when it passes the shared-engine p99 0.0015 and maximum 0.005 error gate, and otherwise falls back to the exact scalar input/output transforms. At most three profile cubes are retained (about 12.6 MiB total). The selected route, cube size, and measured interpolation errors are exposed through the current clip's color metadata for agent inspection. The worker then applies the shared grade cube for static grades, retained full-frame photo-engine sessions for animated grades, shot-match gains, and the external CUBE before publishing one 8-bit QImage to QML. External CUBE tags compile through the photo engine's user-LUT program. The preview attempts a fused Rec.709 cube at 33³ or 65³ over the encoded 0–2 input range; it is used only when every cube-cell midpoint stays within p99 0.0015 and maximum 0.005 error against the exact compiled LUT. LUTs that fail this gate keep the exact source-resolution engine path. The compiled program and optional fused cube share the bounded 64 MiB LRU. LUT assignment rejects tags the photo engine cannot resolve. Export now surrounds each raw creative CUBE with cached, at-most-65³ color-space adapters generated from the photo engine's transfer curves and primaries matrices; it preserves the original CUBE tables and rejects preflight if the full wrapped path exceeds p99 0.0015 or maximum 0.005. The external LUT stage uses trilinear interpolation in both preview and export. The Color inspector exposes ten canonical photo-engine controls (exposure, contrast, highlights, shadows, whites, blacks, temperature, tint, vibrance, and saturation) plus shadows, midtones, and highlights color wheels for hue, saturation, and luminance. Each wheel drag updates the same persisted recipe used by preview, export, and MCP, with one undo snapshot per gesture. The grade LUT cache holds up to eight entries within a 64 MiB table-payload budget; misses reload validated content-addressed sidecars before compiling, and the disk cache is pruned against a 64 MiB budget after writes. Parsed external LUTs use a 64 MiB LRU cache capped at 32 entries. Color-setting changes advance the frame generation so stale work cannot publish. Cached-render playback bypasses raw-source grading because its color is already rendered. The preview still clips to 8-bit SDR and applies QML effects after the LUT. Pixel-format fallbacks, HDR delivery, metadata-mismatch detection, and full-frame shared-renderer parity remain open. Unsupported recipe compilation is surfaced through the playback `colorGradeError` property.
- The photo engine has `ColorAdjustmentState`, `RenderExecutor`, retained `RenderSurfaceBacking`, compiled grade programs, and ACES 2 output processing. The 33-cube returned by `build_color_lut()` is one optimized pointwise stage, not a replacement for the full color pipeline or its spatial layers.
- The engine also exposes in-place frame operations for Sony S-Log decoding/gamut conversion into scene-linear working space and scene-linear-to-Rec.709/BT.709 output. Those operations use two lazily built 16,385-sample transfer curves (about 256 KiB combined) without allocating a pixel copy. They remain the exact fallback when the bounded 65³ display cube misses its validation threshold; retained decoder and GPU surfaces remain open.
- The photo engine CUBE model, parser, serializer, CPU evaluator, compiled user-LUT stage, and Metal stage now retain and apply pure 1D shapers, pure 3D tables, and ordered shaper-plus-3D data. A 1D table stays a compact one-dimensional array; it is not expanded into a dense cube. The timeline bridge applies a linear `lut1d` stage followed by a trilinear `lut3d` stage. For combined files it writes atomic split stages into the timeline LUT cache. It normalizes the shaper sidecar to the default input range and remaps a declared nondefault range in RGB at FFmpeg's negotiated pixel precision before the 1D filter, since FFmpeg's `lut1d` path did not produce the declared mapping when given that range directly. Color-space adapters wrap creative CUBEs without resampling the original LUT, while the timeline still uses FFmpeg rather than the shared photo-engine frame renderer. The current engine parser limits 3D tables to 128³ entries; 1D shapers accept up to 65,536 entries.

- When the render cache is not supplying the Program picture, the playback worker now applies active photo-engine grade recipes from adjustment clips above the Program clip, in lane order and at effective clip/track opacity. Pointwise recipes use the validated shared-engine LUT; spatial recipes use the full photo-engine frame renderer at monitor resolution. The path keeps the existing one-active/one-latest-frame worker bound and includes layer recipe/opacity state in cancellation and performance-cache identity. It skips this source-frame adjustment path if another visible picture layer above the Program clip means the frame would not represent the composite; full multilayer composition still depends on the render cache. Other adjustment-clip effects also depend on the render cache.

For mapped YUV layouts, the preview uses the decoder-reported matrix and range, then restores limited-range RGB into normalized source code values before applying Sony S-Log2 or S-Log3. Layouts that fall back to `QVideoFrame::toImage()` still rely on Qt output representing normalized source code values. The S-Gamut transform uses Sony’s published S-Gamut primaries with a D65 reference; camera-temperature-specific matrix selection and metadata mismatch detection remain open. The shared grade recipe round-trips through Rec.709 before and after its working-space processing, then the live monitor clips to an 8-bit SDR image before QML effects. A visually plausible render is not proof of camera-reference accuracy.

## Target architecture

### One frame contract

Add a video decode adapter that supplies the color engine with frame pixels plus presentation timestamp, duration, bit depth, pixel range, matrix coefficients, primaries, transfer function, and source revision. Preserve decoder-backed or Metal-backed `RenderSurfaceBacking` objects through the graph; materialize CPU `ColorPixel` arrays only for stages that require them.

Each frame runs one canonical sequence:

1. Decode and normalize the declared video range.
2. Apply the selected or detected camera input transform into the photo engine's working space.
3. Run the same grade and layer stages used by still-image editing.
4. Apply the configured Rec.709 or HDR output transform.
5. Publish the preview frame or hand the same rendered pixels to delivery encoding.

The editor and exporter must share the same recipe compiler, stage ordering, color transform code, and cache identity. The render cache may change resolution or quality for interactive playback; it may not change the color decision.

### Source profiles and LUTs

- Represent automatic metadata detection and explicit per-clip overrides in the timeline document. Show the resolved source profile next to the override so a camera guess is visible and reversible.
- Support Sony S-Log2/S-Gamut and S-Log3 input profiles for S-Gamut3.Cine and S-Gamut3 as distinct profile pairs. Preserve normalized source code values and transform to the selected scene-linear working space before creative grading. Sony documents these as distinct camera grading spaces and publishes the S-Log2 code anchors in its [RAW Viewer guide](https://pro.sony/s3/2019/01/24031021/4461641181.pdf) and the S-Log3 behavior in its [technical summary](https://pro.sony/s3/cms-static-content/uploadfile/06/1237494271406.pdf).
- The engine LUT model and timeline browser support 1D, 3D, and shaper-plus-3D CUBE data, declared domains, and declared input/output color-space tags. Validate before attachment, retain the source asset identity, and compile/cache the representation used by both preview and export. For creative CUBEs, the timeline converts declared input/output spaces with engine-derived adapters around the original table; full-frame color management for source metadata and HDR delivery remains open.
- Treat a technical input transform and a creative look as separate ordered stages. Users can bypass or replace either independently.

### Grades and working layers

Store a versioned, undoable grade recipe on clips and adjustment layers. Reuse photo-engine controls and color semantics for exposure, white balance, tone, curves, wheels, channel mixer, LUTs, and masks. Layers need explicit order, enable/bypass, opacity, blend mode, mask ownership, and keyframe timing. Unsupported spatial operations must report their render capability rather than silently becoming FFmpeg approximations.

### UI and agent control

- Add a focused Color workspace with source transform, grade layers, scopes, LUT selection, and before/after comparison. Keep the main timeline's normal editing surface calm; show the deeper controls only when Color is active or a color layer is selected.
- Register color operations as typed timeline commands. The same command must be callable from the UI and the local agent interface and must use the existing undo, save, recovery, and render-cache invalidation paths.
- Expose inspect, set, add-layer, reorder, bypass, compare, and render-status operations with stable clip/layer identifiers. Return the resolved input/output profiles, changed values, warnings, and affected timeline range so an agent can verify its edit.

### Memory and compute budgets

- Avoid keeping multiple full-resolution float copies of a frame. A 3840 x 2160 RGBA-float surface is about 127 MiB before masks, decoder buffers, and compositing intermediates.
- Set explicit budgets for decoder surfaces, in-flight frames, GPU working textures, CPU fallback surfaces, grade/LUT compilation, and disk cache. Reuse frame pools and evict by project/range and last use.
- Compile immutable color programs when recipes change, not once per frame. Coalesce slider updates, cancel superseded frame generations, and prioritize visible playback over background cache generation.
- Playback diagnostics now show smoothed preview-frame time for decode/normalization, creative-LUT preparation, camera transforms, grade compilation and application, timeline effects, shot-match/creative-LUT application, and total frame processing at the rendered dimensions. They also report hit, miss, eviction, entry, and accounted payload figures for the grade-state, grade-LUT, and parsed creative-LUT caches. The same timing and cache data, playback health, adaptive quality, and dropped-frame count are available through the read-only `timeline.inspect_playback_performance` MCP tool. These byte figures cover cache-accounted vector payloads; renderer plans, decoder surfaces, GPU allocations, and other process memory remain unmeasured. CPU/GPU fallback and long-sequence budgets remain open.

## Delivery sequence and gates

1. **Engine video input:** the S-Log3/S-Gamut3.Cine and S-Log3/S-Gamut3 math, Sony code-anchor checks, 23³ engine LUT checks, and staged FFmpeg bridge are implemented; S-Log2/S-Gamut now uses the ACES/OCIO Sony curve definition and staged bridge. Existing automated anchors cover S-Log3; S-Log2 reference-frame and playback proof remains open. Common SDR YUV decoder tags now use the engine's shared source-signal resolver for matrix/range/transfer/primaries defaults and limited-range camera-code restoration; compare rendered video frames against independently generated reference frames.
2. **Canonical grade state:** versioned grade recipes and adjustment layers persist with undo, save/reopen, copy, and render identity. The photo-engine preview renders spatial masks and supported image-dependent operations; the sequence exporter now has a bounded full-frame route for supported top adjustment stacks containing spatial work; source-clip grades outside the bounded single-layer case and other spatial placements still need the shared frame graph in delivery.
3. **Preview adapter:** partially implemented for the primary Program monitor with a bounded latest-frame worker, explicit input/output transforms, a validated camera-transform cube with exact fallback, the shared grade cube, shot-match gains, and CUBE LUT evaluation. Still use retained decoder or GPU surfaces, cancellation across every monitor, and an explicit playback-quality policy.
4. **Delivery adapter:** uses source-file matrix/range/transfer/primaries from revision-keyed media analysis and the shared engine resolver before clip effects, restores limited-range camera code values ahead of the shared Sony cube, uses validated pointwise grade cubes in FFmpeg for static recipes, and uses the bounded full-frame route for animated grades. It still uses a separate pixel-decode adapter from preview; compare decoded preview/export frames and route source-clip masks, spatial layers below visible overlays, HDR output, and other unsupported operations through the shared frame graph.
5. **Workspace and agent commands:** the Color inspector has an automatic or manual camera input-transform selector for video clips, shared base grading on video and adjustment clips, and adjustment-layer add/select/enable/reorder/remove controls, layer opacity, blend modes, ten shared-photo-grade controls, and three-way shadows, midtones, and highlights wheels that target the base or selected layer. Base and selected-layer grade controls have keyframe toggles and use the generic curve editor. MCP exposes the same stable-id layer operations, including blend modes and supported grade controls, plus recipe inspect/set/clear, color transforms/LUTs/shot-match gains, ordinary effect-stack edits, adjustment-clip creation, stable-id opacity control, and stable-id keyframe editing for current timeline parameters, including both base and layer grade namespaces. Read-only `timeline.inspect_playback_performance` also reports the current preview route and quality, frame drops, and the sampled clip key with smoothed per-stage timing. A fuller Color workspace remains open.
6. **Performance and fidelity proof:** measure real 4K clips on CPU and Metal, compare color-managed reference frames, stress long sequences, and record frame-time and memory distributions. Set shipping budgets from measurements rather than a nominal target.

The existing [industry-leading timeline checklist](timeline-industry-leading-checklist.md) remains the feature inventory. Its color gate stays open until input transforms, full LUT handling, working layers, preview/export parity, agent commands, and measured runtime budgets pass together.
