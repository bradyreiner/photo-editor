# Masking, Brush, Selection, And Inpainting Remediation Checklist

This checklist is a concrete rebuild plan for the current masking and brush system. It covers manual selection, brush selection, polygon/lasso selection, smart/object selection, mask rendering, and retouch/inpainting. The goal is not to add more visible controls. The goal is to make the workflow accurate, fast, understandable, reversible, and trustworthy.

## Current Code Observations

- `apps/desktop/qml/workspaces/MaskCanvasOverlay.qml` and `apps/desktop/qml/workspaces/MaskView.qml` duplicate smart-selection stroke state and transient tool handling.
- `apps/desktop/qml/workspaces/MaskInspectorSections.qml` exposes a large mask surface, but users must infer which controls affect a mask set versus a source.
- `apps/desktop/src/editor_preview_controller.cpp` stores mask state as `QVariantMap` fields, which makes invalid combinations easy and hard to audit.
- `generate_ai_smart_selection_mask` in `apps/desktop/src/ai_model_runtime.cpp` currently returns "SAM smart-selection runtime is not linked in this build" unless fake test models are enabled.
- Smart selection currently depends on macOS Vision foreground instance masks when available, then falls back to the local color/region-growth `prompt_mask_engine`.
- Brush rendering can use rasterized `segmentationData`, but `engine/src/pipeline/color_adjustments.cpp` still has a per-pixel/per-point fallback path that will not scale for large strokes.
- Inpaint can run LaMa through ONNX when linked and present, otherwise it uses a CPU diffusion/fill fallback while the UI still presents AI-like language in some states.

## Research Inputs

- Adobe Lightroom Classic frames local edits around a Masks panel, main masks, mask components, Add/Subtract/Intersect operations, Brush Size/Feather/Flow/Density, Auto Mask, range masks, and multiple overlay modes: https://helpx.adobe.com/lightroom-classic/help/masking.html
- Adobe Photoshop's Select and Mask workflow emphasizes view modes, real-time refinement, high-quality preview, original-vs-refined comparison, and color-aware/object-aware refinement modes: https://helpx.adobe.com/photoshop/desktop/make-selections/refine-modify-selections/refine-your-selection-and-mask.html
- Lightroom's Remove workflow separates Remove/Heal/Clone, supports detect-object assisted selection, Add/Subtract refinement, generated variations, and clear reset/refine actions: https://helpx.adobe.com/lightroom-classic/help/remove-tool.html
- Qt Quick Pointer Handlers are designed to separate visual UI from pointer behavior and support mouse, touch, and stylus input with composable handlers: https://doc.qt.io/qt-6/qtquickhandlers-index.html
- SAM 2 is a promptable image/video segmentation model intended for interactive segmentation and reports faster image segmentation than SAM in the paper: https://arxiv.org/abs/2408.00714
- LaMa targets resolution-robust large-mask inpainting with broad receptive fields, which aligns with the app's current `inpaint/lama.onnx` direction: https://arxiv.org/abs/2109.07161

## Suggested Execution Order

1. First fix trust: capability labels, unsupported states, model diagnostics, and separate selection versus retouch wording.
2. Then consolidate UI state: one overlay, one active context, typed mask state, and a clear mask/component panel.
3. Then fix brush performance: rasterized stroke cache, live cursor/HUD, pressure/stabilization, and Auto Mask quality.
4. Then ship manual tools: polygon/lasso editing, range sampling, alpha import controls, and matte overlay modes.
5. Then implement real smart selection: SAM/SAM2 runtime or honest Vision/local fallback UX.
6. Then rebuild refinement: morphology, edge-aware matte cleanup, refine brush, and high-quality preview.
7. Then rebuild retouch: explicit remove/heal/clone/patch workflows, real regenerate, variations, and final-resolution patch handling.
8. Finally enforce quality with tests, telemetry, real-image fixtures, and preview/export parity gates.
