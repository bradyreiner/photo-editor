## Exact supported objects

- `timeline.action.createTimelineTrack`: `kind` is video, graphics or audio; stable returned `trackId`. Audio roles include dialogue, voiceover, music, ambience, effects and commentary. Graphics tracks are native video tracks with graphics semantics, not external flattened slides.
- `timeline.action.createTimelineClip`: source asset creation directly from an admitted canonical **existing regular file**, with stable destination track, nonempty assetId, display label, source duration, trim in/out and sequence start. The implementation classifies the local file and rejects incompatible track kinds or overlapping destination clips. Photos/video require a video track; audio requires an audio track. This route does not require inserting a fabricated user-catalog record. `assetId` in these recipes is a stable plan-owned source label; native `createdClipId` is returned by Looksy. Video/audio analysis can be asynchronous; wait for readiness rather than assuming import completion.
- `timeline.action.createTimelineTitle`: native editable text; supported templates basic, headline, lower-third, callout, quote, brand-card. `values.text` is real text; `fontFamily` names registered native fonts. The plans use project font families Space Grotesk, Space Mono, Instrument Serif and Archivo Black. Verify native font resolution, not merely that font files exist.
- `timeline.action.createTimelineGraphic`: native rectangle, rounded-rectangle or ellipse. Fill uses `backgroundColor`; stroke has its own color/width. Text and a filled shape must be separate native objects. Setting `shapeType` makes a shape-only object and suppresses text.
- `timeline.action.createTimelineGenerator`: current source supports desktop-light, transition-veil, linear-gradient, fractal-noise and vector-path. Its vectorPath parameter is an editable native path with M/L/C/Q/Z commands; the optional `looksy-rig-scene-v1` supports hierarchical native rect/ellipse/path/text nodes and transform channels. The five conservative recipes use ordinary title/graphic/clip objects rather than relying on complex rig authoring. This is a possible native upgrade, not proof that the running binary exposes it.
- `timeline.action.setTimelineClipFrame`: explicit fit/fill/stretch, offset, width/height, scale, rotation, perspective, opacity, corner radius, source crop. Offset is **quarter-canvas units**: `offsetX=4*(centerX/W−0.5)`; width/height are sequence fractions.
- `timeline.action.setTimelineClipAnimation`: native numeric keyframe channels with localSeconds relative to the trimmed clip's start. Use opacity/frameScale/frameOffsetX/Y/frameRotationDegrees for normal visual objects; titlePositionX/Y and titleFontSize for eligible text; audioGainDb for audio. Title strings/colors are not numeric keyframe channels: use separate timed native title clips for copy changes. Available channels depend on clip type. Source-time retime is excluded from this action. 1–32 channels, at most 20,000 total keys, ordered valid clip-local times. Interpolation: hold, linear, ease-in, ease-out, ease-in-out, bezier.
- `timeline.action.setTimelineClipBlendMode`: normal, screen, soft-light. C04's three native RGB ellipses use screen; no coral brand palette or synthetic app screenshot.
- `timeline.action.applyDraftBatch`: at most 16 synchronous safe operations and 256 KiB. Imports, saves, exports, matte paths and asynchronous compound work are excluded. Keep imports/readiness/checkpoints outside batches. An uncertain mutation is reconciled through its journal/receipt, never blindly retried.

## Geometry and color traps to avoid

Native QColor is `#RRGGBB` or **alpha-first** `#AARRGGBB`, not CSS alpha-last. `#00000000` is transparent. Title positionX is its horizontal alignment anchor. positionY is the **vertical center of the entire text block**, not its top; use `(top+blockHeight/2)/H`. A graphic shape uses its center in both axes. Shape corner radius is a fraction of its smaller dimension. Animation `frameOffsetX/Y` uses the same absolute quarter-canvas units as the frame action, not a per-frame delta. Keep keyframes on the 30 fps clock where practical. Before declaring a film ready, inspect native preview/output for font fallback, unintended crop, overlapping labels, fades and source/audio readiness.

Graphics-role lanes start at lane index 100000 and render above ordinary media. A full-frame opaque ink graphic on a graphics-role track would hide photos, even if created first. These plans intentionally put their **native ink shape on an ordinary low video lane**, create media lanes above it, and reserve graphics-role lanes for overlays. `createTimelineGraphic` supports an unlocked native video track through the native title implementation. Verify this stack in live structure/preview before continuing. See `timeline_document_controller.cpp:58154` and `:58169` for the distinct lane allocators.

## Native project import and existing examples

`timeline.list_project_inputs` lists opaque startup-granted input IDs. `timeline.import_project_input` accepts only one such `inputId` plus `confirmed: true`; it does **not** accept arbitrary file paths or raw JSON. Startup configuration is `PHOTO_EDITOR_AUTOMATION_PROJECT_INPUTS`, parsed as exact path+sha256 entries. This investigation does not change that configuration or restart the editor to obtain grants. A safe current route for new work is typed creation/authoring once root has resolved the active-window situation.

The import implementation accepts complete native project schema **version 8**, validates a canonical UUID, tracks and sequenceFormat, and creates a fresh managed Timeline ID while retaining clip/track IDs. Existing examples are schema evidence, not finished campaign files or portable templates: many source/render paths point to older temporary roots and may be offline.
